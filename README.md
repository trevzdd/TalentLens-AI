# TalentLens

An HR analytics dashboard built with Python, pandas, scikit-learn and Streamlit. It covers five things a people-analytics team does: describing a recruitment pipeline, matching candidates to a job, measuring a hiring funnel, predicting attrition with honest evaluation, and auditing that prediction for group differences.

**Live demo:** https://talentlens-ai-edgf9fzr9kcat9shpsefqy.streamlit.app

> **All built-in data is synthetic.** It was generated by simple rules I wrote (`synthetic.py`). A model trained on it re-discovers those rules, so the numbers show how the methods work, **not** what happens in real companies. Nothing here is validated for real hiring or firing decisions.

## Features

| Tab | What it does | Method |
|---|---|---|
| Pipeline | Filter candidates, see current status and source mix, export CSV | pandas |
| Job matching | Rank candidates for a job, with points per part and missing skills | Transparent rule-based score (skills 70, languages 20, experience 10). No ML; weights are my assumption |
| Hiring funnel | Stage-to-stage conversion, days between stages, time-to-hire, results by source | Computed from stage dates |
| Attrition model | Predict who may leave; test metrics, confusion matrix, drivers | Logistic regression, stratified split, 5-fold CV, class weights |
| Fairness audit | Compare flag rate, true/false positive rate by gender or age group | Group metrics + flag-rate ratio (0.8 screening threshold) |

## Design decisions worth noting

- **Honest evaluation.** On the synthetic data the model scores ROC AUC about 0.8, but its *accuracy* (about 0.70) is below the baseline of always predicting "stays" (about 0.86), because leavers are a minority. The app shows both and explains why accuracy alone misleads.
- **Protected attributes are not features.** Gender and Age are excluded from the model and used only in the fairness audit.
- **Reproducible.** Fixed random seeds, 25 unit tests.
- **Bring your own data.** Every tab accepts a CSV upload. The attrition tab works with the public *IBM HR Analytics Employee Attrition* file (check its licence): column names already match. Real data usually gives a much weaker model than the synthetic demo.

## CSV formats

**Candidates:** `ID, Name, Experience, Skills, Languages, Status, Source` (Skills and Languages comma-separated)

**Hiring funnel:** `CandidateID, Source, Applied_Date, Screening_Date, Interview_Date, Offer_Date, Hired_Date` (dates `YYYY-MM-DD`, empty if the stage was not reached)

**Employees:** `Attrition (Yes/No), MonthlyIncome, YearsAtCompany, YearsSinceLastPromotion, DistanceFromHome, JobSatisfaction, WorkLifeBalance, OverTime, Department`. Optional for the audit: `Gender, Age`.

## Run locally

```bash
pip install -r requirements.txt
streamlit run app.py
pytest
python scripts/make_sample_data.py   # regenerate the synthetic datasets
```

## Structure

```
app.py          Streamlit interface (tabs)
matching.py     rule-based match score
funnel.py       funnel conversion and time-to-hire
attrition.py    attrition model and evaluation
fairness.py     group fairness metrics
synthetic.py    synthetic data generators
data.py         candidate CSV loading and validation
data/           synthetic CSVs
scripts/        data regeneration
tests/          unit tests
```

## Limitations

- Synthetic data; metrics are not evidence about real organisations.
- Funnel conversion needs stage dates; "Pipeline" shows current status only.
- Matching is exact text matching: "Excel" and "MS Excel" are different skills.
- Removing Gender and Age does not guarantee fairness: other columns can act as proxies.
- The fairness audit checks one attribute at a time on one test split and uses a rule of thumb (0.8), not a legal test.
- Associations are not causes: overtime may be a symptom of a problem, not the reason people leave.
- Predicting who might leave can harm people if used for firing, promotion or monitoring. Under the EU AI Act, AI used in employment is classed as high-risk.
